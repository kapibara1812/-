# 月次振り返り

- トレード記録 data source: `collection://2f166534-a101-4545-8501-994fdf145f68`
- 月次振り返り data source: `collection://33c49b17-af2a-4f0b-aa2e-9974289be894`
- パターン仮説 data source: `collection://1e7791f3-56be-4175-b562-6150d34bea89`
- 買う前チェックリスト: https://app.notion.com/p/40f7e1c3646581f18158d5ede4785515

## 手順

1. **対象月を決める**: 指定が無ければ前月。
2. **データ取得**: `notion-query-data-sources` の rows モードで、`決済月 = YYYY-MM` の行を取得する（100件を超えるときはページを分ける）。比較のため前月分も取得する。
3. **集計**: 取得した行を `trade-journal/data/month.json` に JSON配列（各行のプロパティ名をそのままキーにする）で保存し、`trade-journal` ディレクトリで実行する。
   ```
   python3 -m tradelog stats data/month.json --month YYYY-MM
   python3 -m tradelog stats data/month.json --month YYYY-MM --json
   ```
   数字はこの結果だけを使う（自分で計算しない）。「デイトレ日次」のページは1日＝1件として数えられるので、デイトレの実際の取引回数は `取引回数` の合計を別に示す。
4. **振り返りを書く**: 集計結果と、各トレードの本文（悪かった点・次回気をつけること）を読み、次をまとめる。
   - 今月の成績（前月との比較）
   - 勝ちパターン（良かったタグ・勝ちトレードに共通すること）
   - 負けパターン（多かった失敗タグと、その損失額）
   - 市場別・スタイル別で差が大きいところ
   - 来月の重点テーマ（1〜3個。確認できる行動の形で）
   - 項目別の成績（保有想定・買いのタイプ・25日線・追加買い・撤退ラインを決めた時期・イベント・テーマ）で差が大きいところ
   - 撤退ラインの執行（ラインどおり売れたか、当日安値・終値との差）と、保有想定とのずれ
   - 未反省のトレードが残っていれば件数
5. **Notion に登録**: 「月次振り返り」DBに1ページ作る（同じ月が既にあれば更新する）。
   - プロパティ: タイトル（例: 2026年10月）、対象月（その月の1日）、取引数、勝率(%)、損益(円)、日本株損益(円)、米国株損益(円)、プロフィットファクター、ペイオフレシオ、最大ドローダウン(円)、多かった失敗タグ（上位3つまで）、来月の重点テーマ
   - 本文: `stats` の Markdown 出力と、手順4の振り返り
6. **パターン仮説の更新**: 「パターン仮説」DBの各行について、`検証条件` に当てはまるトレードを**全期間**のトレード記録から数え、`該当トレード数` `該当の勝率(%)` `該当の損益合計(円)` `最終更新` を更新する（数字は `stats` の項目別の結果を使う）。
   - 目安: 該当5件以上で傾向がはっきりしたら「傾向あり」、10件以上で一貫していれば「確定（ルール化）」を本人に提案し、了承されたら「買う前チェックリスト」に反映する。逆の結果なら「否定」。
   - 今月の項目別の成績から新しい仮説が見えたら、行を追加する（ステータス「仮説（未検証）」）。
7. **報告**: 要点を3〜5行でチャットに書き、ページへのリンクを伝える。
